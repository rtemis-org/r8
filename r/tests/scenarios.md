# The tests of R8 in R

`Rscript tools/scenarios.R` writes this file from the test files; a test compares the two.

## Scenarios

What happens to a user: 66 scenarios, of which 1 are open, since what R8 is to do is not decided or not implemented. Scenarios of packages install them, at several versions where a package is updated, and run in fresh R sessions.

### A. One session: a user declares a type again at the console

| | What happens | The situation | The risk without a check | What R8 does | Tested with |
|:--|:--|:--|:--|:--|:--|
| A1 | a type declared again unchanged changes nothing | A user runs the same script twice in one session. | The values that the first run built are refused, or differ from those of the second. | The values are valid, and equal those of the second run. | one session |
| A2 | a value of an earlier declaration can be looked at, and is used once it is updated | A user declares a type again with its fields in another order, and then reads, changes, and compares a value built before. | A write replaces another field than the one it names, since each field has another position. | The value prints and gives its fields by name. A write, a comparison, and a document are errors that say what differs. r8_update() gives the value under the new declaration. | one session |
| A3 | a value that the new declaration does not admit is not updated | A user declares a type again with a tighter bound, or with a new field that has no default. A value built before is outside the bound, and lacks the field. | The value is written or hashed as one of the new declaration, or becomes a field of another value. | Every use of the value is an error, and so is r8_update(), which names what the value lacks or violates. | one session |
| A4 | a method refuses a value of an earlier declaration | A user declares a type again with a tighter bound, and passes a value built before, outside the bound, to a function that takes the type, to a generic that dispatches on it, and to a method of a base generic. | The function receives a value outside the bound. | Each call is an error that says what differs. | one session |
| A5 | a struct is refused once the struct it extends changes | A user declares a struct and another that extends it, builds a value of the child, and declares the parent again with another field. | The child keeps the fields of the earlier parent, and methods of the parent meet a value of another shape. | The declaration warns that the child is stale.
